Cumulative writing decoder

Implementation handoff · 12 October 2026

What changed

The live 3,000-word deque remains a display buffer. It no longer defines the semantic training dataset. cumulative_semantic.py indexes all eligible trials from every recording directory, incorporating context_trials.jsonl overrides. It stores phrase text, masked multiscale EEG features, and local MiniLM embeddings in a private SQLite archive beside the recordings. Unfinished phrases and missing/unusable contexts remain excluded.

Every successful fit uses all indexed examples. Two batched passes calculate the same standardized, clipped ridge objective as the previous batch solver. Memory depends primarily on feature and embedding dimensions, not recording count. This is cumulative retraining of a lightweight baseline, not a newly validated transformer. Raw EEG and text remain available to develop better sequence models later.

Storage and compute

  • semantic_archive.sqlite3: private text, features and embeddings. Never publish or upload it.
  • semantic_checkpoint.npz: local model plus up to 256 recent retrieval phrases and embeddings. Also private; never treat it as a shareable weight file.
  • semantic_result.json and evaluation_history.jsonl: current and historical evaluation metadata.
  • shared_learning_contract.json: local feature/model compatibility metadata and local profile identifier. This is not an upload permission.
  • One CPU thread, 1.5 GiB process guard, 180-second parent timeout. Embedding batches are committed during indexing so retries reuse expensive work. Changed sessions are rebuilt; unchanged sessions are skipped. A very long session may need further resumable feature-indexing work if even cached processing exceeds the time budget.
  • Resource cost grows with archive size. The retrieval library is still bounded to 256 phrases; this does not limit the training history. Older phrases influence weights even when they are no longer retrieval candidates.

Evaluation is separate

The primary test randomly holds out five-minute time blocks across recordings, with a 30% assignment probability. A persisted local random seed fixes block assignments across updates. Training examples whose EEG context overlaps any held-out block's expanded context are excluded (60 seconds before onset, plus a one-second margin). This applies across session boundaries too. Exact text repeats between train and test are excluded from scoring. The evaluator requires 16 train and 16 test phrases and at least two reserved blocks; it scores at most 256 phrases chosen by stable random ranking, rather than taking only the earliest test phrases.

The separate live model is refit on all indexed examples. The learning curve evaluates chronological training prefixes against the same random-block test. This estimates prediction within the represented recording periods; it does not establish performance on a new day or person. Repeated checks and within-block dependence make the displayed phrase-level chance range exploratory. The model remains unvalidated.

Participant identity

The current boundary is one local data directory, with a persistent random local-profile identifier. That is appropriate only if one person supplied that directory's writing. Signing in as another account does not establish that old recordings belong to that account. Multi-person use of one computer requires explicit local profile selection, isolated storage, and migration of legacy recordings with known provenance. Do not silently pool unidentified legacy sessions.

Cross-user preparation implemented

shared_learning.local_round_update calculates an in-memory numeric gradient delta over every indexed local example. It requires explicit consent, a compatible feature schema/model family, parent-model identity and round identity; it rejects invalid dimensions and nonfinite values, and clips the update norm. The app does not call or upload this result. Tests cover refusal without consent, schema mismatch, clipping, and cumulative use of examples.

The global model must supply the same normalization and embedding coordinates to every client. Averaging independently fitted personalized ridge weights would mix incompatible coordinate systems and is not the planned protocol. The adapter uses one common model and one gradient step; clipping and participant weighting change the optimization objective, so equivalence to centralized training is not promised.

Required before shared training can be enabled

  1. Establish local participant ownership and separate profiles on shared computers. Bind versioned consent to each profile and purpose.
  2. Use Supabase for authentication, consent records, round metadata and versioned global-model storage with tested row-level security. No private archives, individual gradients, text or embeddings should enter general-purpose tables or logs.
  3. Deploy a maintained secure-aggregation coordinator and client protocol, including dropout recovery, authenticated participant membership, replay protection and minimum cohort enforcement. Supabase alone does not implement this protocol.
  4. Define the threat model, minimum cohort, collusion limits, and protection against differencing overlapping cohorts. Never release a singleton or under-threshold aggregate.
  5. Decide whether to add participant-level differential privacy, then implement clipping, noise and a privacy accountant. Clipping alone and secure aggregation alone do not make the released model private.
  6. Validate signed/versioned global artifacts and reject mismatched parent models. Keep a rollback path and enforce size/shape limits. Select a stable normalization policy using approved public or privately aggregated statistics.
  7. Test clients disconnecting, withdrawn consent, corrupted updates, account deletion, malicious updates and recovery. Explain that deleting source data cannot guarantee erasure of its influence from a previously released global model; define retraining policy before enrollment.
  8. Run participant-held-out evaluation comparing local-only, global-only and personalized-global models. Ship shared training only after the protection and learning paths have been tested end to end.

Activation and verification

The semantic worker defaults to cumulative training even for requests from an already-running older backend. Thus Update test can backfill and load the new checkpoint without interrupting capture. Restart after saving to load revised lifetime-count labels, checkpoint restoration and scheduling. If a worker fails, revised backend code retains the last working model and reports the failure.

Tests: tests/test_cumulative_semantic.py checks 3,240 archived words / 1,080 phrases, cache reuse after reopening, changed-source replacement, and numerical equivalence to the original batch solver. tests/test_shared_learning.py checks the local round adapter. These tests establish software behavior, not biological decoding accuracy.
